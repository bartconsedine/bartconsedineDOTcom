# Phone approval for Morning signal TV

On a compatible TV browser, open `/tv` and choose **Show QR code**. Scan with the phone camera, sign in with an enrolled Google administrator, compare the eight-character code with the physical TV, and choose **Approve TV**. The TV polls every five seconds and starts the rotating feed automatically. Google sign-in returns to the reviewed local approval page through the existing protected login continuation cookie. Signing in alone never approves a TV.

The TV reads that administrator's own `morning-feed` / `screen-v1` saved document, not invited/shared feeds. When separately enabled, it also lists and marks that owner's news reading progress. It cannot edit feed records or authenticate to any other app. Ordinary authenticated TV mode and mirroring remain available. The physical TV must support this website's JavaScript and first-party cookies.

## Remote navigation

The `/tv` pairing and connected screens select a usable control automatically. Arrow buttons move spatially up/down/left/right with wrapping at the edge. OK/Enter, Select, Accept and Space activate the highlighted control. Tab/Shift+Tab also cycle inside the current screen or open dialog. A bright yellow fill, outline and dark outer ring identify actual browser focus; moving selection scrolls it into view. Mouse/keyboard focus stays synchronized. During loading, when no actionable control is available, the current screen/dialog is highlighted until a usable control returns.

Selection skips disabled, hidden, inert and collapsed controls. Background refresh, ticker changes, briefing visibility, resize and removed elements preserve valid focus or choose a nearby replacement. Focus stays inside the topmost QR/disconnect dialog. Back/Escape/BrowserBack/Backspace resumes the ticker reader, closes source details, or cancels disconnect; it does not accidentally navigate away. Disconnect uses an app dialog with **Keep connected** selected first. Failed disconnects keep the dialog and pairing; success alone returns to the unpaired screen. Holding OK does not repeatedly activate controls.

The same controller runs in ordinary authenticated **TV mode**; editor inputs and non-TV ticker interactions retain their native behavior. With remote navigation active, all four arrows select controls. To change headlines or routine slides, select the previous/next control and press OK. Press OK on a headline or **Pause / show QR** to open its phone QR. In the article reader, use arrows between **Resume ticker** and **Open article**, or Back to resume and restore headline focus.

Selection is temporary presentation state, with no database write, localStorage, new setting, credential or migration. The receiver must deliver ordinary browser arrow/OK/Back keyboard events; an Omarchy input-driver/remote mapping is outside this website. Physical remote compatibility needs a check on the actual device.

## Durable state and authorization

`private.morning_tv_devices` stores SHA-256 hashes of independent 256-bit device and approval secrets, the approving owner's ID, creation/pairing/session expiry, and revocation. Pairing expires after ten minutes and approval is atomic and single-use. The device secret never enters the QR, query string, rendered HTML or JavaScript. It stays with the pending approval secret in a Secure (production), HttpOnly, SameSite=Strict cookie scoped to `/api/tv`. This cookie is an authentication credential, not application storage. Pairing and access state remain authoritative in Supabase across reloads, server instances and devices.

Raw secrets travel in TLS-protected RPC bodies; do not log request bodies or approval query strings. The phone URL contains only the independent approval capability. `/auth/tv` uses no-referrer policy and no indexing. QR generation runs locally on the website server through pinned `qrcode`; no QR service receives a token. Never paste a real approval URL into public bug reports.

The capability RPC has no direct table grants; the private table has RLS enabled. A private SECURITY DEFINER function with empty search_path enforces each operation; the public wrapper is SECURITY INVOKER. `anon` receives private schema USAGE and permission on the scoped private pairing function, not private table access. The separately gated news-progress function below adds only owner-bound list/mark operations. Direct RPC callers must prove the raw device secret for every read/forget (passing a stored hash fails). Approval, inspection, listing and owner revocation require the live verified administrator session; owner IDs and expiry durations are never browser inputs. Reads recheck the owner's current enrollment and matching verified Google identity. No service key or additional server secret is required.

Pending requests are serialized, capped at 1,000 globally, and expired/revoked rows are cleaned on the next start. This is a storage bound, not a per-IP anti-abuse service; deployment-level rate limits can be added if needed. Connected sessions expire after 30 days; there is no silent renewal. Database errors show failures, never demo state or an authentication bypass.

## Refresh and revocation

The connected screen checks saved feed data every 30 seconds. A database/network failure retains the previous snapshot with a visible warning and retries. An explicit expired/revoked response clears the displayed private feed; local session expiry also clears it even offline. Disconnect on the TV revokes its credential before removing the cookie. On the phone, `/auth/tv` lists only your currently connected TVs and can revoke each by its confirmation code. Revocation takes effect on the next successful TV refresh (normally within 30 seconds). Clearing TV cookies removes local sign-in but does not itself revoke the stored grant; use the phone manager if needed.

## Bart TV navigation and launcher branding

`/tv` is branded **Bart TV** with a dedicated manifest, SVG mark, square PNG icons (180, 192, 512) and a 1280×720 PNG banner under `public/tv/`. Public-site BC branding is unchanged. The TV title is absolute, with application-name and Apple/PWA metadata scoped to `/tv`.

The app has a real Home screen and same-document History API entries for News, Briefing, Calendar and Commands, plus article/source/disconnect overlays. Back closes the top overlay first, returns one previous screen next, and yields to browser/host exit at Home. Selecting Home collapses to its initial entry. Direct links such as `/tv?view=news` seed Home behind the requested screen. Reload preserves valid history state. URL selectors are presentation only and never grant access. Existing Next history state and owner selectors are preserved.

This is required by inspected OmarchyTV upstream `1d97942b03be0e2f5584958dc610299ab1ccf88d`: `launcher/app/src/main/java/com/omarchytv/home/WebAppActivity.java` intercepts native `KEYCODE_BACK` before JavaScript, uses `web.canGoBack()/goBack()`, then `finish()` at root. DOM key prevention alone cannot control that remote button. The same source loads a fresh WebView URL or restores saved WebView state. The web code can provide correct history, but installed-version behavior, Android host exit and physical remote operation still need verification on the device.

### Existing Omarchy tile name and icon

**A website manifest/favicon update does not rename or replace an existing Omarchy web-app tile.** `LauncherConfig.java` reads `webapps[].name` and `.icon` from `<external files dir>/omarchytv.json` (usually `/sdcard/Android/data/com.omarchytv.home/files/omarchytv.json`). `AppAdapter.java` loads a bitmap only when `webapps[].icon` is an absolute local path; otherwise it uses its built-in `ic_web`. It does not fetch the website favicon or manifest. Config is reparsed when the JSON changes; the app list needs a normal launcher refresh/reload afterward.

For the existing Bart web-app entry, preserve its actual `id`, URL, UA, dock references and every unrelated setting. Set only `name` to `Bart TV` and `icon` to the absolute device-local path of the supplied `icon-512.png`, after placing that PNG on the device. Do not replace the complete config with an example or recreate the web app. No TV credentials, other settings or grants need change. The 16:9 `banner-1280x720.png` is also supplied, but the inspected PC `icons push` API validates Android package names and rejects `web:<id>`; `bannerOverride()` is called for native packages before web apps are appended. Do not claim that pushing this banner will replace a web-app tile. The verified web-app path is the explicit local PNG icon field.

No host config or installed launcher was changed by this website PR. Actual launcher rename/icon refresh is a separate device-side step requiring the exact existing entry and approved device connection. The new assets are ready at `/tv/icon-512.png`, `/tv/icon.svg`, and `/tv/banner-1280x720.png` once deployed. Upstream reference: https://github.com/piermark/omarchytv/tree/1d97942b03be0e2f5584958dc610299ab1ccf88d .

## Viewport correction and embedded articles (November 1)

TV display uses a 100dvh grid with compact persistent header/navigation, a minmax(0,1fr) content track, and fixed controls. News, briefing and agenda titles use lossless measured text pages when content exceeds their pane. Every page concatenates back to the original source text; no AI rewrite, clipped excerpt, hidden overflow substitute or document scrolling is used for reading. Summary pagination holds automatic advancement after the first page. Resize/font reflow recalculates page boundaries. The normal admin editor remains a document.

Selecting a headline now opens its public URL in a same-app iframe reader instead of an article QR. Reader Back returns to News and its unread queue when progress is enabled; Summary shows the complete original newsletter copy in fixed pages. The iframe permits scripts and same-origin rendering, but no forms, popups or top navigation; no-referrer prevents leaking the workspace URL. Third-party content may scroll inside that frame. A permanent notice offers the summary when a publisher blocks framing, requires authentication or fails to load. Cross-origin browser security prevents reliable automatic detection of every blocked frame. Nothing proxies or strips publisher security headers; there is no automatic external-tab fallback. Login/pairing QR is separate and retained.

Representative public checks on November 1: the NYTimes issue article returned HTTP403 with X-Frame-Options DENY; GitHub returned HTTP200 with X-Frame-Options deny and frame-ancestors none; cra.mr returned HTTP200 without a framing-denial header. Universal full-article embedding is therefore impossible in the website alone. Omarchy's stock WebAppActivity owns one WebView; the website has no documented bridge to create a second native article WebView. A host change would be necessary for a fully native universal article browser.

Calendar access is unchanged by this layout release. See [the proposed narrow device consent](CALENDAR_DEVICE_PROPOSAL.md); it is a design for approval, not an activated grant or implemented endpoint.


Saved briefing/card links use the same embedded reader in TV mode. The reader is portaled into the visible app root so it remains available while News is hidden or the ticker is off. Return to TV restores the originating screen/control; Card details shows the original saved body without sending it to the third-party iframe. The normal non-TV editor retains its existing link behavior.
Only the saved card ID enters presentation history; title, URL and body are resolved from the currently authorized feed when opening/restoring the reader. Removed/disabled cards cannot be restored from stale private history payloads.

## Owner news progress capability

Once separately authorized and enabled, a paired TV may list and append the owner’s news read markers through `/api/tv/news-progress`. Markers belong to the owner, survive disconnect/re-pairing, and are shared with the owner’s signed-in sessions and other TVs. Feed editing, Calendar and other apps remain outside the TV capability. Existing paired credentials gain this narrow capability only after explicit activation approval; until then the UI reports that progress is unavailable. See [progress storage and rollout](../tldr/README.md#saved-reading-progress-november-1) for the migration, activation and recovery requirements.
