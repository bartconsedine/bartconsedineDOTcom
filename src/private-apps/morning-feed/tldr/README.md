# TLDR news wire

The Morning signal app and paired `/tv` display show the public latest issues of TLDR Tech, AI, Dev, InfoSec and DevOps. The ticker is independent of the 24 manually curated routine/briefing cards. TV mode can open with zero cards; Hide morning briefing leaves only the ticker. The optional personal morning briefing remains available.

Each issue includes every extracted editorial article, including Quick Links. Explicit sponsor/advertisement items are excluded wherever they occur. We expose headlines, complete public archive summaries, public URLs, edition labels, issue dates and source freshness metadata. URL duplicates retain all edition/date labels. News content uses public sources; the separately persisted reading progress below requires its reviewed migration.

## Sources and history

`https://tldr.tech/<edition>/archives` is authoritative for the available public issue dates; the archive currently links `/ai/YYYY-MM-DD` as well. Older issues advances one archive issue per edition, with independent dates displayed. No article-count cap is applied, and the ticker cycles through the whole selected group of issues. History is limited to dates listed by the public archives (up to page 999); public archives can lag email. Source details explicitly label older issues, stale cache and unavailable editions.

`server.js` uses Next's existing Data Cache for disposable **public source results**, revalidated every 30 minutes. A thrown fetch/parser/link failure preserves the last successful entry; each edition has an independent key, with checkedAt included. It contains no owner or session data and is not authoritative app storage. Public archives remain the source of truth. There is no durable imported user dataset or integration job state. The browser polls every minute and keeps loaded headlines after failures, including the unavailable edition's last-loaded entries after a partial cold-cache failure. A first visit with no successful source cache honestly shows unavailable/empty sources and retries. Cache eviction plus source outage cannot reconstruct an issue that has never loaded on that browser.

Ticker on/off, briefing visibility, issue page, current headline and pause are disposable presentation controls. Read status is durable owner-scoped Supabase data. Fresh sessions and returning to News choose the newest unread story in the selected issues. Existing saved routine data stays in owner-scoped Supabase.

## Safe links

Only explicit article heading links are parsed. Named/numeric entities are decoded, marketing parameters removed, and functional parameters (YouTube v, document IDs, public publisher share parameters) retained. Credentials, IP literals, non-web schemes, custom ports, local/internal domains, subscriber/unsubscribe/referral destinations and ad hosts are rejected. Public archive `link(s).tldr.tech` redirects are resolved with a four-redirect bound. Every network target is DNS-checked against non-public/reserved IPv4 ranges and the validated address is pinned into the TLS request, preventing DNS rebinding; IPv6-only targets fail closed. Responses have byte and time bounds. Link validation failure throws for the entire edition rather than caching a silently truncated issue. Article selection uses the same-app sandboxed reader described below; no article QR is generated. Authentication pairing QR remains separate.

The existing TV API verifies its pairing before returning the ticker. Pending/expired/revoked screens cannot fetch it. The existing admin app dispatcher still verifies live identity and owner/grant scope before its GET handler. The reading-progress endpoint adds only the narrowly scoped capability below. Responses remain private/no-store; only the public upstream cache is shared.

## Saved reading progress (November 1)

Opening an article marks it read; manually selecting Next, Previous, or an upcoming headline marks the story being left. Automatic rotation does not mark anything read. The default queue excludes confirmed reads; **All stories** includes them with a Read label, and **Unread stories** returns to the queue. An all-read issue shows “You’re caught up” and keeps checking for arrivals. An open reader keeps its snapshot even after its story leaves the unread queue. Save failures remain visible inside and outside the reader and retain a retry action; no failed save is reported as successful.

Every issue group sorts by descending newest TLDR issue date across all editions, then canonical URL for stable ties. TLDR archives expose date-level issue metadata, not precise publisher publication timestamps; the UI does not invent timestamps. Refresh and retained unavailable-source stories use the same ordering.

`private.morning_news_reads` stores `(owner_id, article_id, read_at)` indefinitely. Article IDs are SHA-256 hashes of the same canonical public URL used for deduplication: tracking parameters and fragments are removed while functional article parameters survive. No article body, title, URL, browser token or user identifier is stored in a marker. The only writes are idempotent insert-if-absent marks; parallel sessions cannot replace or lose a whole read list. An existing marker keeps its first-read timestamp. There is no mark-unread/reset writer. Removing admin membership cascades its markers; revoking a TV does not delete the owner's progress.

`/api/admin/news-progress` uses the live signed-in administrator, independently of a shared app owner selector. `/api/tv/news-progress` accepts only the existing HttpOnly TV cookie and resolves its live verified owner in SQL. Neither endpoint accepts an owner ID. The SQL function rechecks session/device expiry, revocation, membership and matching verified Google identity; both tables have RLS and no client table privileges. Shared Morning signal viewers/editors receive no progress endpoint and cannot see or update the feed owner's reading history. Progress refreshes every minute, on window focus/visibility return, and on entering News. Pairing/session expiry still requires normal sign-in or re-pairing; the new connection resumes the same owner's saved unread queue.

### Deployment and rollback

Requires reviewed migration `20261101014448_morning_news_progress` (checksum in `scripts/reviewed-migrations.mjs`). It installs the tables and scoped RPC **disabled by default**. No hosted write or activation is implied by a website release. Follow the [guarded migration runbook](../../../../docs/CLOUD_DATABASE_MIGRATIONS.md), inspect the exact pending suffix, confirm a current recovery point, and use its fresh encrypted backup gate. Obtain explicit authorization for this hosted migration and for enabling the new read-history/list-and-mark capability on existing paired TVs before changing the private settings row. No credential or membership changes are needed. Missing schema, disabled settings and database failures show real unavailable/setup states; there is no browser-only persistence fallback.

The authorized activation is `update private.morning_news_settings set enabled=true where singleton`; disabling the same flag stops list and mark access while retaining saved rows. Never expose a client setter for the flag. Code rollback leaves additive schema and progress intact. Do not remove rows or edit applied migration bytes as part of a rollback. If an older per-device read-marker prototype exists, it is not the source of truth for this owner-scoped feature; no silent data conversion is attempted.

Progress is maintained through the reviewed runtime RPC actions `list` and `read`, bound to a live session or paired capability. This is not an editable generic app-data JSON document. Chat maintenance must not use privileged SQL to select another owner's history or forge device credentials; a future reset/import operation needs its own reviewed contract.

Local verification covers canonical identity, newest-first order, a delayed stale list, failed/unconfirmed saves, reload/new-session resume, concurrent session refresh, passive-rotation exclusion, explicit navigation, caught-up arrivals, cross-origin/selector denial, both owners and TVs, expired/revoked/pending devices, live identity removal and direct-table denial. The PostgreSQL 17 recovery drill includes restored markers, owner isolation and revoked-device denial. Browser fixture checks are distinct from hosted persistence and physical-TV acceptance.

## Controls and verification

OK/Enter or Open article opens the public link in an embedded reader and freezes that headline across background refresh. Back/Escape/Backspace resumes. In `/tv` and authenticated TV mode, all four arrows move the highlighted selection spatially and OK activates it; select the previous/next headline buttons to change headlines. Tab cycles within the active dialog. Outside the managed TV screen, the ticker keeps its existing Left/Right headline and Up/Down control shortcuts. The separate ticker toggle and Hide/Show morning briefing controls are available in TV mode. Reduced-motion preference disables automatic advancement and horizontal motion. The selected issue retains all articles independently of routine cards.

Tests cover extraction above 24 articles, sponsor placement, deduplication, safe URL parameters, private/reserved/mixed DNS, redirect bounds/address pinning, history, stale metadata, source/parser errors, pairing denial, pause/refresh/Back, revocation, empty sources and reduced motion. Real browser QA uses a temporary local fixture route removed before release; it is not an authentication bypass in production. Physical Google TV remote compatibility, OmarchyTV installation and TV wake are separate and require the user's actual device. Content scheduling, opening `/tv`, and physically powering on a TV are distinct operations.

## Editorial TV layout (October 2026)

News now uses a stationary, balanced two-line headline target and the **complete original TLDR archive summary**, preserving paragraph and bullet text. There is no marquee, ellipsis, line clamp, AI rewrite or excerpt limit. Font fitting uses measured line height to reduce long titles to a two-line target; pathological titles retain all their text and can use additional lines instead of clipping. The source summary appears directly underneath at TV-readable size, with a compact upcoming-story rail. Different summaries for the same URL in different editions are retained and selectable. The reader snapshots the selected summary as well as the public link; refresh cannot replace the paused story. Reading duration scales with source word count (24–180 seconds); reduced motion advances only manually. No claim is made that unseen private email bytes were compared; displayed text is explicitly labeled as TLDR archive copy. The public cache version advances so old headline-only cache entries are not reused as summary data.

TV mode has News, Briefing, Calendar and Commands sections, retaining the existing spatial D-pad/OK controller. Back returns through actual previous-screen history, closes source details, or closes the article reader. Switching sections preserves disposable News state; hidden News does not auto advance. The reduced header and dark editorial palette replace the oversized controls and empty 8vh top gap.

The old Hide/Show briefing control had no visible effect with zero enabled cards because ticker-only mode was always forced while the button still appeared active. It now explicitly says **No briefing cards** and is disabled in that state. The Briefing section explains how to add/enable real cards without inventing content. With cards, Show opens Briefing and Hide returns to News; choices survive the existing 30-second refresh. A fresh entry begins at Home; reload preserves valid browser history and selected view. This remains disposable presentation state, not a new saved database preference. No durable settings or database schema changed.

Calendar is a read-only projection of the existing Calendar companion GET API, not a second calendar store. Only an already authorized owner web session can request it; the existing endpoint independently verifies ownership and Google connection. The existing Morning signal-only paired TV credential and shared viewers see a locked explanation and never request Calendar data. Calendar access on a paired physical TV still requires separately reviewed owner authorization; this release adds no grants or OAuth scopes and does not alter events. Owner access denial clears a previously loaded agenda. Commands has an explicitly disabled input and no endpoint: it cannot send, acknowledge delivery, or silently expand the screen's authority. Connecting commands requires the separately reviewed actual-dot transport, an authorized sender/session scope, validated command input and real delivery receipt/error semantics. PR25 remains separate.

Issue source status now opens a dedicated modal with full-width archive cards, human-readable dates and relative freshness. Raw ISO diagnostic timestamps and nested inline archive links no longer expand into the news-reading layout; Back closes the source panel and restores focus.

Bart TV now starts at Home. Real browser history, not only keydown state, backs screens and overlays; this matches OmarchyTV's native Back interception. Home → News → Calendar → Commands backs through those screens; Article and source overlays close before leaving News. Selecting Home collapses the app's own stack. See the [TV integration and branding notes](../tv/README.md) for host limitations and actual launcher icon configuration.

Visual QA used an isolated noninteractive WebKit 26 renderer against the local app and intercepted public/test fixtures at 1920×1080 and 390×844. It accessed no Chrome profile, existing browser session or locked desktop. News rendered a two-line 76px headline and complete source summary, plus Home, article and source panels; mobile/remote/native history/direct-link/empty-card/locked-calendar paths were exercised. A ResizeObserver feedback warning and active-tab hover contrast issue found during rendered QA were fixed and the run passed with zero page errors. This is rendered fixture evidence, distinct from physical Google TV or installed OmarchyTV verification.
